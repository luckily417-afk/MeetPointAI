## 3. 圆形 / 多边形硬约束测试

### 3.1 圆形

1. 设置 A=天津站、B=天津大学；
2. 区域模式选「圆形区域」，半径 3 千米，点「地图选圆心」，在地图上点天津站附近；
3. 点「智能推荐」。

**预期**

- 地图出现半透明圆，推荐点全部落在圆内（程序对每个结果做 `contains` 复验，日志里 `区域硬约束校验：通过`）；
- 把半径改到 0.1 千米 → 提示"当前指定区域内未找到符合条件的见面地点，请扩大搜索范围或调整场所偏好。"，**不得**自动扩大半径。

### 3.2 多边形

1. 区域模式选「多边形区域」→「绘制多边形」→ 连续点击 5 个点 → 双击闭合；
2. 拖动顶点微调，点「智能推荐」。

**预期**

- 半透明多边形填充；推荐点全部在多边形内（含边界）；
- 故意画"蝴蝶结"（自相交）→ 立即提示"多边形存在自相交，请重新绘制"；
- 顶点少于 3 个点闭合 → 提示"顶点不足 3 个，无法闭合多边形"。

## 4. AI 无效推荐拦截测试

无需真实调用模型，测试用假客户端注入 5 类坏输出：

```powershell
& $py -m pytest tests\test_ai_validation.py tests\test_pipeline.py -q
```

| 坏输出 | 期望 |
| --- | --- |
| `poi_id` 不在候选集合 | 拒绝；`errors` 提到该 ID；重试后仍失败 → `source=rule`、提示"AI 返回的推荐未通过校验" |
| 重复 `poi_id` | 仅保留第一条 |
| 理由中含坐标数字（如 `117.2100,39.1350`） | 拒绝该条 |
| 推荐区域外候选 | 拒绝该条（`region.contains` 复验） |
| 非 JSON / 空 | 拒绝并重试（默认 3 次），最终降级 |

手工验证方法：把 `algorithms/ai_validator.py` 的 `build_ai_messages` 中 system 提示词临时弱化，或在 `.env` 里把 `DEEPSEEK_MODEL` 换成不存在的模型名，观察界面提示。

## 5. 断供与降级测试

### 5.1 模拟 DeepSeek 断供

```powershell
# 方法 A：改错 Key（重启程序）
$env:DEEPSEEK_API_KEY = "sk-invalid"
# 方法 B：改错域名（模拟 DNS/连接失败）
$env:DEEPSEEK_BASE_URL = "https://api.deepseek.invalid"
```

**预期**

- 顶部 DeepSeek 胶囊变红（鉴权失败/连接失败），tooltip 给出 HTTP 码与错误原因；
- 地图、搜索、路线全部可用；

## 9. 输入与设置回归（新增）

```powershell
& $py scripts\ui_check.py      # 半径输入 / 单位换算 / 推荐数量 / 设置对话框
& $py -m pytest tests\test_inputs.py -q
```

覆盖的实际问题：

| 现象 | 现在的结果 |
| --- | --- |
| 中文输入法把 26 上屏成「〢〦.〇」或全角「２６」 | 校验器接受并归一化为 26；`valueFromText` 正确得到 26.0 |
| 数值控件把 26.0 显示成「〢〦.〇」（zh_HK 等区域 `zeroDigit=〇`） | 启动时 `QLocale.setDefault(QLocale.c())`，并对数值控件显式设置 C 区域，显示恒为 ASCII |
| 半径单位只有千米 | 增加「千米 / 米」切换，切换时数值自动换算（26 km ⇄ 26000 m） |
| 大圆（26 km）结果全挤在圆心附近 | 候选改按 A、B 中点排序并做等距抽样，26 km 实证覆盖华山里/奥城/全运村等不同方位 |
| 推荐数量固定 | 左侧按钮上方「推荐数量」1–10 即时生效；「工具 → 设置」可改并写回 `.env` |
